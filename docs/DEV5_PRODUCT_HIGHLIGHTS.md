# dev.5 产品亮点与发布叙事（开发快照，尚未正式发布）

> **状态：`2.5.0-dev.5` 已有代码实现，但尚未完成真实 B站/DSH Desktop 端到端验收，也不是当前正式发布版。** 公开介绍时必须使用“计划”“希望让”或“正在开发”；只有端到端验证通过后才把有关表述改为现在时。大肥鱼是有持续模拟情绪的 AI 角色，不是被证实拥有意识或真实情感的生命体。

## 定位文案

**主标题**：不只是会回复的大肥鱼，更是一只会记住朋友、带着好奇心生活的 AI 角色。

**短描述（适合 README / 社区帖）**：

> 大肥鱼 Plus 正在探索一种更有生活感的 AI 社交：朋友可以通过私信或 @ 留下视频邀请，陌生人的私信愿望也可以成为短期灵感。大肥鱼不会照单全收，而是结合真实看过的内容、持续模拟情绪与兴趣，在合适的时候决定要不要去看看。主人在公开视频下的授权互动，则通过独立受限 Agent 安全执行，并用自然的语言回应。所有主动推荐都尊重好友退订、权限、频控与可核验结果。

**一句话卖点**：**朋友的邀请不是命令，陌生人的愿望不是任务；好奇心、真实经历与安全边界共同构成大肥鱼的社交生活。**

## 三个可讲述的场景（设计示意，不是运行截图或已发生事件）

### 情绪唤起的朋友邀请

周一，好友说“有空看看这条深海视频”。大肥鱼把邀请放进有限期候选池，没有立刻执行，也没有承诺会看。周三浏览 B站时，真实的海洋主题让它产生了好奇；经过只读权限、BV 与时间预算核验，它选择了好友推荐的那条。后来如果好友允许私信推荐且大肥鱼确实有话想说，它可以自然地聊起自己的**真实观看经历**，而不是自动发一条“任务完成”。

### 陌生人的许愿

陌生人私信说“希望大肥鱼以后多看看天文”。审核通过后，这只是一条短期探索灵感，不会把对方变成白名单好友，也不会触发任何点赞、评论或保证回复。如果大肥鱼后来自己真的看了天文视频，才可能在长期真实经历中逐步形成相关兴趣。

### 主人公开评论中的自然互动

主人在视频评论中 @ 大肥鱼：“给这条点个赞吧。”只有**平台真实 UID 核验、评论所属 BV 核验和独立点赞授权**都通过，系统才会尝试点赞。操作得到明确成功回执后，若公开回复功能也单独允许，可能自然回复“点上啦～🐳”；无需把内部命令状态、私聊历史或好友资料发布到评论区。也可以选择不回复，防止刷屏。

## 可以宣传什么，不可以宣传什么

| 可以作为完成后的卖点 | 必须避免的误导性说法 |
| --- | --- |
| 有证据的社会邀请、情绪相关的择机观看 | “AI 自己产生了真正的感情／拥有意识” |
| 同一 UID 的好友偏好、退订与恢复 | “认识所有 B站用户”／“随意向任何人私信” |
| 陌生人私信安全心愿只作为候选灵感 | “陌生人发一句话就能让大肥鱼执行任务” |
| 主人公开评论受限 Agent，执行后自然回应 | “所有评论指令都能执行”／“任何时候都能评论” |
| 私密上下文隔离、独立授权和真实回执 | “完全不会泄露隐私”／“永远不会出错” |

## 发布页面建议结构

1. **首屏短故事**：朋友推荐的视频几天后被想起；突出“自愿选择而不是机械待办”。
2. **核心能力对照**：陌生人灵感、好友邀请、好友退订、主人评论 Agent，明确每种身份能做什么。
3. **真实演示**：本人授权的录屏或经过脱敏的真实事件链；展示“收到邀请→候选→已观看→可选回复”，并标注尚未执行时的状态。
4. **安全模型**：身份核验、公开/私信隔离、逐动作授权、退订优先、发送前复核、结果未知不重试。
5. **上手配置**：推荐默认关闭自动发送、公开评论 Agent 默认关闭，主人可逐项启用并先使用草稿。
6. **诚实边界**：模拟情绪不是意识，AI 对视频的“观看”描述须与真实证据一致；真实效果依赖 B站、DSH 和模型配置。
