# dev.9 · 双域意愿系统（Dual-Context Agency）

## 目标

主人在主 Session 中下达正式任务时，大肥鱼应在工具权限、安全规则与能力范围内执行；主人在 B站生活场景出现时，只是在发出请求，大肥鱼可以基于持续衰减的模拟情绪与关系经验进行选择。主人身份不会因为转到私信或评论区就自动变成“不得拒绝”的执行权。

## 接入链路

- 主 Session：本次不修改其命令与工具执行链，不经过双域意愿门。
- B站主人私信：`index.js#getNewDmMessages()` 中，在主人受限 Agent、旧版只读待办和旧版动作入口之前，对可识别请求先评估。受限 Agent 模型自行规划出动作时，`lib/owner-dm-agent.mjs` 另有执行前防绕过校验。
- B站主人公开 @：`lib/owner-comment-agent.mjs#accept()` 先确认真实 UID、视频来源、评论时效、独立功能权限和重复请求，之后对「点赞」及「自然邀请」进行意愿判断；未同意时不会进入真实操作。
- 不匹配动作请求的普通交流不进入这层门。投币仍无工具，因此不会借此创建投币权限。

## 决策

- 三态：`allow`（愿意尝试）、`defer`（推迟）、`refuse`（拒绝）。后两者不执行工具。
- 参考：活力、社交意愿、好奇心、情绪倾向；若有白名单关系成长记录，可给长期熟悉者有限加分。
- 同一人、同一渠道、同一动作与 BV（如已知）的后续新请求，可以参考最近 12 小时中温和请求次数。只有真实不同的消息 ID 才增加次数；超过上限不再累积，过度施压反而降低接受倾向。
- 不会因软磨硬泡绕过身份、功能开关、私信许可、发布审查、时间窗、额度或去重。该判断只可能拒绝已被允许的动作，不能授予新权限。
- 同一视频下的简短温和追问（例如 `@大肥鱼 拜托啦`）仅在前 12 小时已经拒绝一条自然观看邀请时，可以再次触发自然邀请。绝不会继承「点赞」或其他写入授权。

## 审计和隐私

`<stateDir>/dual-context-agency.json` 保存匿名哈希、时间、事件类别、决定、简化的情绪评分和重试计数，不包含原始 UID、私信正文、目标 BV 或主 Session 内容。文件具备大小、版本与符号链接检查，写入使用临时文件替换。

`<stateDir>/owner-comment-agent.json` 继续存储公开评论 Agent 的去重及动作状态；拒绝或推迟会记为 `skipped`，原因以 `low-willingness-defer` / `low-willingness-refuse` 表示。用户不要因为 `skipped` 就认为未收取 @。

## 验收建议

1. 主 Session 按原有权限执行同类只读任务，不受模拟情绪阻拦。
2. 在「人生记忆/模拟情绪」中将活力调低（测试环境，结束恢复）；用主人私信提出新的真实请求，检查意愿账本和无外部写入。
3. 再在同一 BV 下用不同新评论 ID 温和请求；确认可能由拒绝变为愿意考虑，同时不保证一定发表。
4. 重复轮询同一消息，确认不多次回应、不积累劝说次数。
5. 关闭点赞或公开评论权限，再反复请求，确认无外部操作。
6. 仅发送普通聊天、明确的退订或恢复推荐句子，确认不会被意愿门错误认作执行命令。

## 已知限制

- 意愿判断是可测试的角色模拟，不是实际生理情绪或意识。
- 目前仍是偏保守的文本分类器，复杂间接表达需要后续扩展；不保证所有自然语言请求都可识别。
- 主人私信 Agent 分流前会独立观察认证主人新鲜、明确的推荐偏好（包括退订与恢复）；它不属于可因模拟意愿拒绝的执行命令，也不会重放 Agent 首次启用前的历史私信。
- 未在真实 B站生产账号执行端到端测试；新代码需要在 DSH Desktop 实例中验收。
