# `2.5.0-dev.3` 自主回忆深化与事实边界（开发版）

本页记录的 **v2.4.99 预留设计**和 **dev.1 首版实现**属于历史说明；以下为 dev.3 当前目标和安全约束，不代表 main 正式版已经具有这些功能。

`dev.3` 对真实已入选视频及已发生的自身评论进行候选关联；先要求早于当前事件的 `life-reflection` 记忆及原始 `c-...` 证据 ID，再允许本地同 BV、标题重复或谨慎的两字符主题片段提示「可能相关」。主题重合不是人物关系、心情因果或真实观看视频画面的证据。主人设置的情绪阈值、检索数量只影响能否检索和是否评估，不会授予任何发送权限。对外私信只到配置中的主人 UID，主 Session 分享只到显式指定的在线会话，继续受免打扰、冷却、授权和去重约束。

B站动态草稿使用单独的无工具模型路由，默认沿用互动模型，**不沿用人生反思模型**；B站公开动态编辑不读取私人聊天记忆。经认证主人发送的「大肥鱼 现在看 BV号」只允许只读视频资料检查，完全不授予点赞、评论、关注、私信其他人等写入权限，不得把读取简介、字幕或评论描述为完整观看画面。

`dev.3` 的管理页提供最近评估的状态与原因码；记录只含时间、候选数、渠道和简短原因，不记录记忆正文或私信内容。仍需真实 DSH Desktop 和 B站账号端到端验收。

# 情绪驱动的自主回忆：v2.4.99 边界与 2.5.0-dev.1 开发实现

> 本页原有内容记录 v2.4.99 预留而未实现的设计。本次开发快照 `2.5.0-dev.1` 已接入一个保守的、默认关闭的首版实现；尚未完成真实 DSH Desktop / B站私信端到端测试。以下仍保留过去版本的事实边界与未来方向。

## 2.5.0-dev.1 新增范围

- 情绪状态不保存具体触发的原始消息。当前使用**最近 6 小时的可用模拟情绪**与**最近 2 天真实入选视频**作为候选条件，不声称已精确识别产生情绪的原因。
- 仅从 `long-term-memory/dafeiyu.json` 中，选择由 `life-reflection` 基于旧 `c-...` 原始候选生成的 `experience` 回忆；对照 `life-memory/candidates.json`，核验关联的真实旧 BV 或明确的标题重复片段，并确保旧经历至少早于新事件 2 天。
- 无工具的模型仅返回 `skip` 或已验证 `memory_id` + 已允许的渠道。回忆正文由旧记忆原文及新 BV 组成，模型不得额外虚构细节。
- 两种独立出口：B站已登记主人 UID 的私信、指定且在线的 DSH 主 Session 的 `agent.followup`；不会同时群发。总授权、两个出口和额度都默认关闭。
- 限速：默认每天最多 1 次实际发送、两次评估间隔至少 24 小时、09:00–22:00 安静时间窗之外不发送；同一个新旧回忆对记账去重，重启仍保留。
- 管理中心支持不外发的模型评估预览；返回信息不等于发送成功。

## 尚待进一步增强

- 情绪与具体观看/互动事件之间更精确的因果关联，而不是当前严格保守的时间共现。
- 在不泄露隐私的前提下，扩展主人共同聊天经历、关系转折和多模态感知等额外回忆触发源；本版**不**从会话目录扫描私人聊天记录。
- 主 Session `followup` 在不同宿主版本的 UI 展示、B站接口真实回执和平台风控，需在实际账号测试后才可标注已完成端到端验收。

# 主动回忆状态：v2.4.99 预留设计（尚未启用情绪触发）

## 当前事实边界

现有 v2.4.98 起存在模拟的角色状态（可用于节奏/语气等），**不是**可靠推断角色心境或过去经历的事实传感器。因此 v2.4.99 不添加“心情相似度”加权检索，也不让该状态生成已发生事件。

未来需要的只读“当前状态”接口可按维度提供：

```text
当前状态（预留，部分维度已有独立数据来源）
├─ 兴趣：已确认的观看证据和主人核心兴趣
├─ 社交需求：权限、冷却、当前互动意愿
├─ 好奇：当轮内容和已有浏览倾向
├─ 疲劳/活跃度：活动频率、最近任务与休息边界
├─ 心情：情绪触发召回能力【暂未启用】
└─ 当前惦记：真实待办及其原始来源
```

## 将来满足条件时的建议流程

```text
可验证的当前状态/心情信号（先定义可靠性）
  → 仅提议只读关联关键词（不得写入记忆）
  → 本地/语义检索返回真实 memory_id 与 source_event_ids
  → 按 ID 读原始经历并对账
  → 在会话/计划中形成“一个可能的念头”
  → 由现有权限与额度系统单独判断任何外部行动
```

不可靠的状态或缺少原始证据时，直接跳过主动联想，不输出历史事实。

## 不可变的事实来源原则

1. 原始经历、时间、BV、真实消息 ID 是独立的证据；反思不应覆写这些记录。
2. 人生回忆是可追溯、有候选 ID 的摘要；兴趣趋势是可更新的判断，不允许倒改旧事件。
3. 主动想起的念头不是事实，不能直接成为记忆来源或外部行为授权。对于任何新事实，只接受新的可验证事件。
4. 冲突时回到原始事件对账，保留旧摘要的来源和修订历史，避免反复压缩导致偏好夸大。
5. 任何低成本检索模型只做读取、候选 ID 选择与排序，不能执行写入、更新或发消息。

## 本版功能范围

v2.4.99 仅实现源事件边界提示、独立的任务择机决策、有限跨视频标题线索；不存在情绪驱动的记忆联想开关，更不存在自动怀旧发动态的路径。

## 同一开发快照中的主人 B站私信控制（与自主回忆权限隔离）

私信远程操作使用独立 `ownerDmActionsEnabled` 总开关和每类权限（点赞、收藏、关注、评论草稿、评论发布、动态草稿、动态发布、白名单好友私信），全部默认关闭。必须由收件箱确认发送方 UID、固定单行命令且最近 15 分钟；不会把自主回忆的 `emotionRecallDmEnabled` 作为其他写操作的授权。重复消息 ID、失败后回执不确定、已尝试发布的草稿都不可自动重试。独立自主待办规划器不能因此自动写入 B站。生成草稿不是公开发表，发布必须另一条明确指令。
