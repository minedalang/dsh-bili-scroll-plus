## 功能与权限测试

- [ ] 陌生人私信的视频愿望只进入经审核、限额、可到期的候选灵感池；陌生人评论 / @ 不会进入此通道。
- [ ] 陌生人不能修改好友名单、私密画像、待办或任何 B站写操作权限；假主人 UID 和昵称不生效。
- [ ] 好友私信与 @ 的意愿流入同一 UID 画像；文字中的“这个视频”只能绑定平台核实的当前 BV。
- [ ] 模糊愿望不被误判为永久兴趣；临时兴趣可过期，稳定兴趣须有明确或重复证据。
- [ ] “以后别推荐了”强制停止该好友所有主动视频分享，仍保留本来允许的正常聊天。
- [ ] 同一 UID 明确恢复才可重新订阅；普通正面反馈不能取消退订。
- [ ] 已生成推荐草稿在发送前仍执行最新的退订、渠道、冷却、限额与 BV 去重检查。
- [ ] 好友邀请首先进入只读候选，不因通知到达就执行、回复承诺或新增高权限待办。
- [ ] 模拟好奇情绪只能影响候选排序，不能改变硬性权限、预算和是否能发送。
- [ ] 真正观看后才记录相应级别的经历；不能以视频元数据冒充观看完整画面。
- [ ] 主人评论 Agent 只接受真实主人 UID + 真实评论所属 BV；评论正文不允许换目标或越权。
- [ ] 主人评论 Agent 没有主 Session、私信历史、私密待办、其他好友画像与密钥的读取入口。
- [ ] 评论草稿生成和公开发布分开授权；所有写操作先记账后执行，状态不确定不自动重试。
- [ ] 自然回复只根据本条已核实信息与真实执行回执生成；沉默也是有效选项；失败不伪称成功。
- [ ] 关闭评论 Agent、关闭 @、额度耗尽、网络中断或禁言时不出现多余公开回复。

## 兼容性与回归

- [ ] 从最新 `dev.4` 升级可保留旧 UID 名册、独立推荐渠道、历史偏好、退订记录、主人私信 Agent 账本与旧配置。
- [ ] 默认设置不因迁移而开启新增公开 @、陌生人主动回复或 B站写操作。
- [ ] 首次启用新监听只建立历史基线，不批量处理旧评论、旧私信；跨重启重复通知不重复执行。
- [ ] 通过所有 Node.js 测试、Python 测试和 `node selfcheck.mjs`；无测试因新功能被绕过。
